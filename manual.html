1. Instalação e ambiente virtual

O projeto usa um ambiente virtual em .venv. Sempre ative-o antes de usar o bot — sem isso, o terminal não encontra o comando nem as dependências:

# Dentro da pasta do projeto:
source .venv/bin/activate

# Confirmar que está tudo instalado:
./bin/meeting-bot doctor
Tudo certo quando: o doctor mostra ✅ em todas as dependências (click, pyaudio, sounddevice, faster_whisper, anthropic, docx, weasyprint, yaml, ffmpeg) e na chave de API.

Se precisar reinstalar as dependências (por exemplo, em outra máquina):

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
Atenção: o pacote av deve ficar abaixo da versão 16 (av<16, já fixado no requirements.txt). Versões mais novas quebram a transcrição do faster-whisper.

2. Configurando a chave de API (.env)

As chaves ficam em um arquivo .env que nunca vai para o git (está no .gitignore). O bot procura o arquivo em dois lugares, nesta ordem:

  1. ~/.meeting-bot/.env — global, vale em qualquer pasta
  2. .env na pasta do projeto (ou na pasta atual)

Passo a passo

# 1. Copiar o modelo:
cp .env.example .env

# 2. Editar o .env e preencher a chave do provedor escolhido:
#    ANTHROPIC_API_KEY=sk-ant-api03-...   (para Claude)
#    OPENAI_API_KEY=sk-...                (para OpenAI)

# 3. Dizer ao bot qual provedor usar:
meeting-bot config set ai_provider anthropic   # ou: openai

# 4. Confirmar:
meeting-bot doctor

Variáveis exportadas no shell (ex.: no .bashrc) têm precedência sobre o .env.

3. Comandos

ComandoO que faz
meeting-bot start "tema"Inicia a gravação de áudio (via ffmpeg/PulseAudio)
meeting-bot stopPara a gravação e salva o arquivo .wav
meeting-bot summaryTranscreve a última reunião (Whisper) e gera resumo com IA
meeting-bot export --format pdfExporta o resumo (md, pdf, docx ou html)
meeting-bot listLista as reuniões (filtros: --date, --tag)
meeting-bot search "termo"Busca reuniões por tema, participantes ou tags
meeting-bot config initCria as configurações padrão
meeting-bot config get [chave]Mostra uma configuração (ou todas)
meeting-bot config set chave valorAltera uma configuração
meeting-bot doctorVerifica dependências, arquivos .env e chaves de API

4. Fluxo de trabalho típico

# Uma vez só (primeira utilização):
meeting-bot config init

# Durante a reunião (em outra aba do terminal):
meeting-bot start "projeto-alpha-sprint-3"

# Ao terminar:
meeting-bot stop
meeting-bot summary
meeting-bot export --format pdf
Primeira transcrição: o modelo Whisper é baixado do Hugging Face no primeiro uso (o modelo small tem ~460 MB). Para algo mais leve: meeting-bot config set whisper_model tiny.

5. Onde ficam os arquivos

TipoLocal
Áudios gravados (.wav)~/.meeting-bot/meetings/
Resumos exportadosexports/ dentro da pasta onde o comando foi executado
Índice de reuniões~/.meeting-bot/index.yaml
Configurações~/.meeting-bot/config.yaml
Estado da gravação ativa~/.meeting-bot/state.json

Para salvar os áudios em outra pasta (por exemplo, no OneDrive):

meeting-bot config set meetings_dir "/home/carnevali/OneDrive/Reunioes"

Cada comando mostra o caminho exato do arquivo gerado na linha 📁 Arquivo: da saída.

7. Solução de problemas

«comando não encontrado»

Ative o ambiente virtual: source .venv/bin/activate. Alternativas que funcionam sem ativar:

./bin/meeting-bot doctor
./.venv/bin/python -m meeting_bot.cli doctor

doctor mostra ❌ nas dependências

Você está no Python do sistema, não no .venv. Ative o ambiente virtual (acima) e rode de novo.

⚠️ chave de API não configurada

Verifique no .env se a linha está exatamente ANTHROPIC_API_KEY=sk-ant-... — sem espaços antes do = e sem aspas. Depois confirme com meeting-bot doctor.

Resumo sai como «placeholder»

Significa que o bot não encontrou chave de API válida. Confira o .env e o provedor configurado (meeting-bot config get ai_provider).

Transcrição vem vazia ou «simulada»

Com áudio sem fala (silêncio), o texto vazio é normal. Se aparecer «[Transcrição simulada...]», o faster-whisper não carregou — rode meeting-bot doctor e confira o pacote av<16.

Gravação não capta áudio

A captura usa ffmpeg -f pulse -i default. Verifique se o PulseAudio/PipeWire está ativo e se o microfone padrão do sistema está correto (configurações de som do Linux).
